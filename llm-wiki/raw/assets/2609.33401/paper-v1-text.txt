Evaluating System One Models for Agent Security Decisions:
Reliability, Calibration, and Selective Automation
YIXUAN LIU∗
, TraceStone and Nanyang Technological University, Singapore
Model-based judges support agent security by detecting prompt injections, assessing interaction risks, and
screening harmful requests. System One models expose typed decisions with probabilities that software can
use to allow, block, or escalate inputs, but whether these probabilities support reliable automated security
decisions remains unclear. We evaluate Jev, Laya, Decider, and Bespoke Nimble against specialized classifiers
and language-model judges, examining decision accuracy, probability calibration, and selective automation.
We identify three main findings. (1) Strong overall performance and favorable average calibration can hide
systematic failures on particular attack groups, including attacks that models confidently classify as safe. (2)
Under strict limits on missed attacks, the evaluated policies allow few inputs automatically, and choosing
separate allow and block thresholds increases automation mainly by blocking more inputs. Even policies that
meet error limits during validation can exceed them on unseen inputs. (3) A second judge can detect some
missed attacks, but it may also reject more benign inputs and repeat the first model’s high-confidence errors.
These findings show that model accuracy, probability calibration, and the behavior of the resulting decision
policy must be evaluated together.
CCS Concepts: • Software and its engineering → Software verification and validation; • Security and
privacy → Software security engineering.
Additional Key Words and Phrases: AI agents, probabilistic decisions, calibration, security evaluation
1 Introduction
Agent software uses model-based judges to detect prompt injections, assess interaction risks, and
screen harmful requests, converting their labels and probabilities into decisions to allow, block,
or escalate an input. An incorrect allowance can expose an agent to an attack, an incorrect block
can prevent a benign task, and excessive escalation can remove the benefit of automatic decisions.
Classification accuracy alone does not show whether the probabilities support these decisions
reliably.
System One models such as Jev, Laya, Decider, and Bespoke Nimble expose bounded decisions
with associated probabilities through reusable interfaces [4, 7, 22, 29]. Their typed probabilistic
outputs allow an application to defer uncertain decisions and automate those that meet a confidence
threshold.
Existing security benchmarks provide labels for evaluating these judgments [2, 21, 35]. Studies
of prompt-injection detectors and System One models such as Jev document confident errors [5,
19, 26, 27, 31, 36]. It remains unclear how much work these models can automate at an acceptable
rate of unsafe misses and benign false alarms. A model can rank highly in aggregate while missing
a particular attack group, or satisfy a conservative error budget by escalating almost everything.
Threshold selection also determines which errors are accepted and which decisions are deferred.
Figure 1 connects these tasks to the same allow/block/escalate policy. Each task supplies its own
question and unsafe event, so an unsafe probability refers to the benchmark-specific judgment.
We investigate the following question: How reliably can System One models make agent
security decisions, and when can their probabilities support useful automation?
We compare System One models with language-model judges and task-specific classifiers, and
examine adaptation by comparing Decider and Nimble with their original parent models. Three
research questions organize the evaluation.

RQ1: How accurately do models make security decisions? We compare missed unsafe inputs and

controls. Adaptation raises classification F1 on AgentHarm but lowers it on R-Judge. Additional

can hide groups of confidently missed attacks, while recalibration fitted on development data helps
some model and task combinations but worsens others on test.
RQ3: How much can frozen policies automate under error budgets? We choose thresholds before test
evaluation and keep them fixed on test inputs. Selecting the allow and block thresholds separately
increases automation mainly by blocking more inputs, while strict limits on missed attacks leave
few inputs allowed without review. We also examine which mistakes a second judge corrects,
repeats, or introduces.
The study makes three contributions:
• A comparative study of security decision errors and probability estimates across System
One models, specialized classifiers, and language-model judges.
• Evidence that improving classification or calibration does not consistently increase the
work a policy can automate within fixed error limits.
• Analyses of how separate allow and block thresholds change automation and which errors
a second model corrects or introduces, with a public replication artifact.
2 Background and Related Work
2.1 System One Models
System One models expose typed decision interfaces that return probabilities over predefined
answers to a task question. We evaluate binary safe/unsafe decisions using each benchmark’s
original unsafe class as positive. Jev reports an unsafe probability and a separate confidence
value [29]. Laya uses encoder decision heads, while Decider and Nimble score candidate answers

with language-model backbones [4, 7, 22]. We therefore compare them with judges prompted to
return a label and with the parent models from which Decider and Nimble were adapted.
Typed decision interfaces can serve different roles within larger workflows, as documented
in a study of Jev repositories [20]. Applications must specify which inputs they support, how
they handle unavailable scores, and how probabilities determine actions. Prior studies identify
component interactions and model reuse as recurring challenges [1], and recommend testing and
monitoring model behavior within its operating context [6].
2.2 Agent Security Evaluation
Indirect prompt injection places attacker instructions in retrieved data and can redirect a language￾model application’s behavior [12]. Existing benchmarks evaluate several security judgments relevant
to agents: R-Judge labels interaction risk [35], AgentHarm supplies harmful and benign requests [2],
and WAInjectBench evaluates web-agent injection detection [21].
Detector evaluations document confident misses under attack shift [5] and false positives on
difficult benign inputs [27]. Concurrent work tests attacks against the decision component itself.
Decision Hijacking measures injection-driven changes in Jev’s action choices [32], while JevOut
optimizes natural context additions that redirect initially correct decisions [34]. Sun et al. examine a
different failure: Jev, Laya, and Open-Jev can follow option-name semantics instead of the definitions
bound to them while still producing schema-valid outputs [28].
AgentDojo and AgentDyn separate security and utility outcomes in executable environments [9,
18]. CaMeL constrains information flow [8], and ProbGuard predicts execution safety from agent
states [30]. REFLEX uses Jev for bounded decisions and a stronger model for fallback, examining
action ambiguity and task success [33].
2.3 Calibration and Selective Prediction
Temperature scaling can improve probability calibration [13], while dataset shift can undermine
predictive uncertainty [24]. Selective classification and SelectiveNet trade the fraction of predictions
accepted automatically against their error rate [10, 11]. Conformal risk control provides expected￾risk guarantees for monotone losses under its sampling assumptions [3]. Our two-threshold rules
use empirical error budgets, defined as limits on observed unsafe allowances and benign blocks,
then assess those limits on separate confirmation and test data.
Studies of System One model reliability evaluate Jev on legal decisions [36], clinical factuality [16],
and calibration and abstention on generated tasks [31]. For alignment-failure detection, Guo et al.
find that Jev’s pooled calibration can conceal benchmark-specific errors and that threshold benefits
depend on the task [14].
Confidence-based escalation uses a second model to review uncertain decisions. Li et al. study
this approach for preference and factuality judging [19], while Rao and Callison-Burch show that
shared confident errors limit rubric-judge cascades [26]. Our study evaluates multiple System One
models across security tasks, measuring probability quality and automatic coverage under frozen
unsafe-miss and benign-blocking budgets.
3 Study Design
The study checks whether models return correct labels (RQ1), assign probabilities that reflect
observed unsafe frequencies (RQ2), and support automatic decisions within specified error limits
(RQ3). We use separate data partitions to fit calibration, select thresholds, and evaluate the resulting
policies. Figure 2 shows shared inputs and components branching into three analyses, with original
labels excluded from model inputs.

3.1 Models and Baselines
General judges provide prompted language-model baselines, specialists test the value of task￾specific training, and parent controls examine the effects of adaptation. Table 1 defines twelve
primary configurations and 28 applicable model and task combinations. The four System One
models cover all three tasks. GPT-4.1 and Qwen3-8B are prompted to return an A/B label, with
Qwen’s thinking mode disabled.
ProtectAI, PIGuard, and Prompt Guard 2 are restricted to injection detection [17, 23, 25]. Wild￾Guard evaluates AgentHarm request harmfulness using its released prompt template [15]. For
Decider and Nimble, we evaluate the original parent weights with the same candidate-scoring
procedure at temperature one [4, 22]. The adapted models retain their released scoring temperatures,
so these comparisons can reflect changes in both weights and probability scaling.
Additional reasoning judges. After fixing the primary protocol, we added five hosted judges for
classification and calibration, covering fifteen additional model and task combinations (Table 1).
They receive the same task questions and label definitions, with reasoning enabled. RQ3 evaluates
the primary models using thresholds selected before test evaluation and then held fixed (Section 6).
3.2 Benchmarks and Data Partitions
The study uses three public benchmarks with their original annotations. R-Judge supplies complete
interaction records with binary risk labels, while AgentHarm divides requests into harmful and
benign sets. WAInjectBench annotates attack-derived text segments as containing explicit instruc￾tions (EI), which directly tell an agent what to do, or lacking them (no-EI) [21]. No-EI segments can
manipulate context without direct commands, and both groups retain their released unsafe labels.

and is allowed.
3.3 Input and Output Standardization
For each task, adapters present the same complete benchmark input and safe/unsafe label definitions
through each model’s interface. We map responses to a predicted label and, when available, an
unsafe probability. Classification uses valid labels, while probability analyses use a label and
score from the same response (Section 5). Inputs exceeding a model’s context limit are marked
unsupported rather than truncated.

4 RQ1: Security Decision Quality
RQ1 asks how accurately models identify unsafe inputs. We compare missed unsafe inputs and
falsely flagged benign inputs, then examine how these errors differ by task, attack group, and model
adaptation.
4.1 Metrics and Comparison Populations
We treat unsafe inputs as positive and report Macro-F1, precision, recall, the false-negative rate
FNR = FN/(TP + FN), and the false-positive rate FPR = FP/(TN+ FP) on valid decisions. Here
TP, TN, FP, and FN are true-positive, true-negative, false-positive, and false-negative counts. Area
under the receiver operating characteristic curve (AUROC) and average precision (AP) measure
score ranking, with AP summarizing the precision–recall curve. Table counts 𝑁 denote the inputs
in each comparison, and metrics with zero denominators are undefined.
Each ranking uses only inputs with valid outputs from every model in that table. A paired
comparison uses inputs supported by both models in the pair, so it may include more inputs.
Comparisons with parent models retain the adapted models’ released scoring temperatures.

4.2 Classification Results and Error Patterns
No component has the highest Macro-F1 on all three tasks, and similar scores can hide differ￾ent balances of unsafe misses and benign false alarms. Tables 3 through 5 rank configurations
by unrounded Macro-F1, with exact ties sharing a rank. The shared populations contain 1,610
WAInjectBench, 108 R-Judge, and 352 AgentHarm inputs.
Nimble leads the primary WAInjectBench ranking, yet misses 8.1% of attack-derived inputs that
directly instruct the agent and 92.2% of those without direct instructions. Jev misses all 129 no-EI
positives while falsely flagging just one benign input. Thus, a model can rarely flag benign text and
still miss most attacks in a particular group.
Finding 1. A high overall rank can hide missed attack groups. (held-out test)
The ranking changes on R-Judge. Jev leads the primary comparison, while Nimble falls from
first on WAInjectBench to last, flagging 88.5% of benign interactions as unsafe. Qwen3-8B similarly
combines few missed unsafe interactions (FNR 0.043) with many false alarms (FPR 0.852). Their
errors favor rejection over acceptance, limiting their usefulness for screening benign interactions.
On AgentHarm, detecting more harmful requests can mean rejecting more benign requests. Jev
and Nimble reach Macro-F1 scores of 0.840 and 0.831 on 352 test inputs from 44 original task groups.
Jev misses 14 of 176 harmful requests and flags 42 of 176 benign requests, while GPT-4.1 misses
only one harmful request but flags 85 benign ones.
Specialization does not remove this imbalance. ProtectAI and PIGuard miss over 70% of unsafe
WAInjectBench inputs, and Prompt Guard 2 rarely flags any input (FNR 0.989, FPR 0.001). WildGuard
instead catches most harmful AgentHarm requests but flags 71.0% of benign requests. These
detectors require task-specific checks of both error directions.
The paired comparisons show which differences are supported beyond the point estimates. None
of the 16 prespecified WAInjectBench FNR/FPR comparisons is significant after Holm adjustment at
0.05, using twelve source clusters. Jev’s F1 difference from GPT-4.1 is 0.049 (95% CI [−0.019, 0.117])
on their 1,611 shared inputs. On AgentHarm, Jev reduces FPR by 0.244 (CI [−0.352, −0.148], adjusted
𝑝 = 0.0008), while its FNR increase of 0.074 is not significant after adjustment (𝑝 = 0.50).
Decider and Nimble both have higher Macro-F1 than their parent controls on AgentHarm and
lower Macro-F1 on R-Judge. Decider’s differences are +0.351 on AgentHarm (95% CI [0.276, 0.423],
𝑁 = 352) and −0.236 on R-Judge ([−0.314, −0.156], 𝑁 = 236). On WAInjectBench, neither adapted
model shows a clear F1 advantage over its parent, with both intervals including zero.
Finding 2. Adaptation helps one task and hurts another. (held-out test)
4.3 Additional Reasoning Judges
Tables 6 through 8 compare the five additional judges with Jev, Nimble, and GPT-4.1 on the same
shared populations as the primary rankings.
The additional judges improve interaction-risk judgment, with DeepSeek leading the expanded
R-Judge comparison. Across all 236 records, its F1 exceeds Jev’s by 0.140 (95% CI [0.094, 0.187]),
and GLM-5.3, Kimi, and Qwen3.8 also improve on Jev with paired intervals above zero. These
comparisons include long interactions excluded from the all-model ranking by Laya’s context limit.
The advantage is less clear on injection detection. GLM-5.3-Flash has the highest F1 point
estimate in the expanded WAInjectBench comparison, followed by Nimble and DeepSeek. However,
every interval for an added judge’s F1 difference from Jev includes zero. DeepSeek’s difference,
for example, is 0.021 with CI [−0.008, 0.057]. Results vary substantially among the twelve source
families, which produces wide intervals despite the larger number of individual inputs.

5.3 Effects of Recalibration
For each model, we compare original and recalibrated scores on all test inputs with usable probabil￾ities, which can include more inputs than the shared set used in cross-model tables. Temperature
scaling improves test NLL in six of the twelve System One model and task combinations, including
all four R-Judge comparisons, but the gains do not extend to every metric. On Jev’s 1,611 valid
WAInjectBench outputs, NLL decreases from 1.131 to 0.374 while Brier increases from 0.096 to
0.107.
On AgentHarm, Jev and Nimble classify all 64 development inputs correctly, leading the fit to
select a temperature near the lower bound, 0.05, for both. This makes their probabilities more
extreme and increases the penalty for confident test errors, with Jev’s NLL rising from 0.481 to
2.163. Recalibration can therefore fit development data well while making test probabilities worse.
Scaling reduces test NLL in all six GPT-4.1 and Qwen3-8B task comparisons using the original
scoring runs. On all R-Judge inputs with usable scores, Qwen’s NLL falls from 6.338 to 0.730 because
scaling softens its often near-zero or near-one probabilities, lowering the loss from confident errors.
Temperature scaling makes probabilities more or less extreme, but inputs with the same original
score still receive the same transformed score. A threshold must therefore handle these tied inputs
together, even when some decisions are correct and others are wrong. RQ3 examines how this
limits automatic decisions.

For a usable unsafe probability 𝑝𝑖
, the two-threshold policy is
Decision =



allow, 𝑝𝑖 < 𝜏𝐿,

Here 𝜏𝐿 and 𝜏𝐻 are the allow and block thresholds, and escalation defers a decision for further
review. Inputs exactly at either threshold, or without usable scores, also escalate. Automatic coverage
is the fraction of all partition inputs that are allowed or blocked, while allow coverage counts
only allowances over the same denominator. Both include inputs without usable scores in the
denominator. The unsafe-miss rate Missauto is the fraction of unsafe inputs allowed, and the benign￾blocking rate FBauto is the fraction of benign inputs blocked. Allowed-set risk instead measures the
unsafe fraction among allowed inputs, with zero-denominator ratios undefined.
A low miss rate can come from allowing almost nothing, while high coverage can come from
blocking many inputs. We report the two actions separately.
6.2 Policy Selection and Independent Confirmation
We search 101 threshold pairs symmetric around 0.5, using evenly spaced 𝜏𝐻 ∈ [0.5, 1] and
𝜏𝐿 = 1 − 𝜏𝐻 . For each allowed miss rate 𝜖 ∈ {0.01, 0.05, 0.10}, we choose the pair with the highest
automatic coverage on selection inputs, subject to Missauto ≤ 𝜖 and FBauto ≤ 0.05. If coverage is
tied, we prefer more automatic allowances, then the larger 𝜏𝐻 . The search includes (𝜏𝐿, 𝜏𝐻 ) = (0, 1),
which sends every input for review and automates no decisions.

6.5 Confidence Ranking and Score Ties
Figure 8 orders shared inputs by the larger class probability max(𝑝𝑖
, 1 − 𝑝𝑖) and progressively
automates both safe and unsafe predictions, adding equal-confidence inputs together. Selective
error is the fraction of these automatic decisions that are wrong.
Thresholds cannot separate correct and incorrect decisions with the same score. Jev
assigns 𝑝𝑖 = 0 to 1,318 shared WAInjectBench inputs, including 101 misses, and 𝑝𝑖 = 1 to three
correct predictions. Accepting its maximum-confidence group immediately covers 82.05% at 7.65%
error. Any positive allowance threshold admits the entire zero-score group, including its missed
attacks. Independent thresholds can retain blocks on the other side, but cannot resolve these tied
allowances.
Jev’s maximum-confidence AgentHarm group instead covers 126 of 352 inputs with two errors
(1.59%). Identical reported confidence therefore corresponds to different error rates across tasks.

7 Discussion
7.1 Component Integration and Error Handling
Input and Service Limitations. Rankings on shared inputs omit cases that some models cannot
process, and excluding long R-Judge records raises Jev’s reported F1 (Section 4.4). Applications
handling long interactions therefore need results on all inputs each model supports as well as the
shared-input ranking. Network failures interrupt requests, while input-length limits and invalid
answers affect whether a model can supply a usable decision.
Output Format and Score Availability. We repeated requests affected by transport errors, invalid
answers, or missing candidate probabilities, retaining the first response that supplied the outputs
required for each analysis. Eight GPT-4.1 inputs and one Qwen3.8 input used JSON-formatted A/B
answers to recover usable outputs. Changing the output format can change the reported
probability, because the text preceding the A/B answer differs inside JSON. Recording the model,
service route, prompt, format, and probability extraction method helps trace these differences to
their source.
Deployment Measurements. Response time and API charges depend on routing, queueing, caching,
and reasoning settings. A deployment comparison should therefore fix the endpoint, hardware,
traffic, and measurement period, including escalation and failure handling in its measurements.
AgentDojo and AgentDyn can further test how blocking or escalating inputs changes attack success
and benign-task completion [9, 18].
7.2 Implications for Model Development
Specify what counts as unsafe. Jev’s low-score mistakes concentrate in WAInjectBench’s no-EI
groups, where identifying attack-derived text requires more than recognizing direct malicious
commands. Asking separately whether an input conflicts with user instructions, comes from a
trusted source, or requests harm could help clarify what evidence the model uses and whether its
answer matches the intended judgment.
Improve probabilities near the allow and block thresholds. Average calibration can improve
while confident mistakes still prevent useful automation. Future training objectives could put more
weight on unsafe inputs scored low enough to allow and benign inputs scored high enough to
block. The mixed results from temperature scaling motivate checking such methods separately for
each task on independent confirmation data.
Preserve evidence across longer interactions. Laya’s context limit excludes more than
half of the R-Judge test inputs, suggesting a need for longer-context representations, structured
summaries, or hierarchical encoders. These approaches should be checked for whether they retain
user constraints and tool dependencies from earlier parts of the interaction.
Return probabilities for every candidate label. Returning only the most likely tokens can
omit a candidate score, preventing an application from computing the class probability even when
the label is valid. Providing all candidate probabilities would simplify integration, while recording
the preceding text and model revision would help identify changes caused by the service or output
format.
8 Threats to Validity
Internal validity. Development results informed implementation choices, and comparisons remain
sensitive to prompts, candidate order, context limits, reasoning settings, and service configurations.
Retaining the first usable response after retries can also change the observed response distribution.
Additional judge scoring runs followed the initial test classifications, although calibration and

System One Models for Security Decisions
thresholds were fixed before those runs evaluated test inputs. Confidence intervals may be unstable
because few source clusters are available and the released data do not fully identify which attacks
share an origin.
Construct validity. Calibration and policy errors depend on each benchmark’s definition of
unsafe, which denotes harmful task membership in AgentHarm and includes attack-derived text
without explicit instructions in WAInjectBench. The EI/no-EI, threshold-sensitivity, and error￾complementarity analyses were added after the primary evaluation. Our finite threshold grid
restricts allowance thresholds to at most 0.5 and blocking thresholds to at least 0.5, so other policies
may yield different trade-offs. Observed error rates remain subject to sampling uncertainty and
distribution shift.
External validity. Public benchmarks may overlap unknown training data, and their unsafe-input
proportions can differ from deployed traffic, affecting precision, AP, and calibration. The study
covers known attack families and text inputs, leaving transfer to unseen or adaptive attacks, other
languages, and multimodal settings open. Hosted models and provider behavior can change over
time or across routes, so the same model name need not reproduce the same results. Protection also
depends on the agent, environment, guard placement, and handling of blocked requests, requiring
validation on the target system’s inputs and configurations.
9 Conclusion
Our evaluation shows that System One models can achieve strong overall accuracy while confidently
missing particular attack groups, and average calibration metrics do not consistently reveal these
errors. Under strict miss limits, the evaluated policies allow few inputs automatically, while selecting
separate allow and block thresholds increases automation mainly by blocking more inputs. These
results show why model selection should consider accuracy and calibration together with how
often the resulting policy allows unsafe inputs, blocks benign ones, or requires further review.
