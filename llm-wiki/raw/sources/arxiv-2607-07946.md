# What the paper reports

- 113 tasks, 91 active open-source repositories, five languages (TypeScript, Go, Python, JavaScript, Rust). Repos need 500+ stars, a permissive license, and active maintenance (sections 4.1, abstract).[^paper]
- Tasks are written from scratch and never merged upstream, so reference solutions stay out of public commit history (section 3.3).[^paper]
- Verifiers are hand-written to check observable behavior and accept any implementation providing it (sections 3.4, 4.2). Each verifier runs three times during authoring to catch flakiness, and every trial also runs regression checks (section 4.2).[^paper]
- Quality assurance: LLM-assisted analysis plus independent human review on four dimensions: prompt-verifier bijection, acceptance breadth, realism, environment cleanliness (section 4.3).[^paper]
- Verifier audit (section 3.4, Figure 5): 30 random tasks per benchmark, 3 rollouts across 9 of the 16 configurations. An independent LLM judge (GPT-5.5 at xhigh effort, run as a Codex CLI agent) disagreed with the SWE-Bench Pro verifier on 67 false-positive and 189 false-negative cases of 789 rollouts (32.4%, 95% CI 29.2 to 35.8). For DeepSWE: 2 and 8 of 735 (1.4%, CI 0.7 to 2.5). The authors call this a disagreement rate between two readers, not a ground-truth error rate.[^paper]
- Prompts are about half the length of SWE-Bench Pro's; reference solutions touch 5.5 times more code and about 2 times more output tokens (abstract, section 1). DeepSWE prompts average roughly 2,000 characters (section 8).[^paper]
- Container hygiene: the task container ships a shallow clone at the base commit (section 3.3). On SWE-Bench Pro the paper cites an external report (Scale AI, 2026) in which 33 of 38 cheating trials read the gold commit from `.git` history (section 7.5).[^paper]
- Setup (section 5): 16 agent configurations, one fixed harness (mini-swe-agent, one bash tool, shared prompt), about 4 rollouts per task, 7,174 scored rollouts, 9,000 second timeout, no step or cost cap. Context exhaustion and timeouts count as failures; provider, verifier and network errors are excluded.[^paper]
- Figure 1 (v1, May 2026): top configuration gpt-5.5 [xhigh] at 70.0% pass@1 (88% pass@4), then gpt-5.4 [xhigh] 55.5%, claude-opus-4.7 [max] 54.2%. Intervals of the mid-table overlap, so rank order there is not statistically separated (section 5.5).[^paper]
- Spread (Figure 7): 69.8 points across eight models on DeepSWE against 29.7 points on SWE-Bench Pro using public scores. The authors note spread is not itself a capability claim (section 6.1).[^paper]
- Efficiency (section 6.2, Figure 8): output tokens, wall-clock time and dollar cost each vary by an order of magnitude and do not correlate strongly with pass rate.[^paper]

# Authors' stated limitations (section 8)

Binary reward with no partial credit. Functional correctness only (no code quality, style, performance). Prompts are still longer and more specified than typical daily requests. Under-specified requests and non-coding agent use are unmeasured. One fixed harness (mini-swe-agent) and mixed reasoning-effort settings. The audit is small (single-digit counts on the DeepSWE side) and the judge, GPT-5.5, is also the top-ranked configuration, so self-preference cannot be excluded. The harness pilot has 10 tasks and was run on SWE-Bench Pro tasks.
