# What the paper says

- Problem: "As agents take on longer and more complex problems, controlling the execution becomes a task in its own right." Each step brings control choices "like which partial work to build on, whether to start fresh, or when to stop." Existing agents often take "each control decision in a single step conditioned on their accumulating history".[^p1][^p2]
- Method (sec 1, 3): agentic meta-reasoning, an inference-time harness. Workers do the task-level work; a controller decides what work to assign. "The controller keeps a compact assessment of progress. Full worker outputs remain in persistent memory." Every stored output (an attempt, a critique, a controller note) is an artifact with a stable identifier. A worker gets the task, a controller-written instruction and a set of artifacts the controller selects; workers never see the controller's private state. A worker is a single model call (reasoning benchmarks) or a coding agent with tools (ProgramBench).[^p2][^p4]
- Control cycle (sec 3.3): four sequential stages, Assess, Propose, Evaluate, Dispatch, each "an agentic process with its own prompts, context, and permitted memory operations and tools". "Between cycles, only a compact state is persisted and each stage may retrieve prior artifacts as needed." Propose is not shown the remaining budget; Evaluate weighs proposals against it ("a prompted, qualitative assessment of computational value rather than an exact optimization"). Dispatch picks the artifacts each worker sees, or issues Stop with an artifact already in memory.[^p5]
- Artifact graph (sec 3.4, 4): an edge from artifact A to B when A was supplied as context for producing B. Diagnostics: budget utilization U = (N_ctrl + N_work) / B; nodes, edges, depth, width; memory reads and writes; coverage (a correct candidate exists by call k); monitoring (Type-2 AUC of worker confidence and controller verdicts); selection Pr(S | C); frontier selection gain against a uniform choice from the deepest terminal artifacts.[^p6][^p7][^p8]
- Matched baseline (sec 3.5, 5.2): the Direct Control Agent uses the same workers and the same interfaces for delegation, context selection, artifact writing and stopping, and "chooses each action in single turn over the accumulated history". "The comparison thus isolates the combined control design, but it does not separately identify the effects of staging, state compression, or memory access." Both get the same nominal model-call budget; controller calls are charged against it. "Equal call allowances do not imply equal token cost, latency, or FLOPs."[^p6][^p9]
- Setup (sec 5): IMO ProofBench-Advanced (30 problems, proof score as a percentage of the maximum), ARC-AGI-2 (120 tasks, exact match), LongCoT-mini (507 problems), ProgramBench (200 program reconstruction tasks; score is the fraction of hidden test cases on which the rebuilt program matches the reference, averaged per problem). Models: Gemini 3.1 Pro, GPT-5.5, Opus 4.8. Budgets: 25, 50, 100 calls on the reasoning benchmarks and 400, 800, 1200 on ProgramBench; main comparison at 100 and 1200. External baselines: RLM on the reasoning benchmarks; mini-SWE Agent, Claude Code (Opus 4.8) and Codex (GPT-5.5) on ProgramBench, with the same budget accounting added. Neither controller is fine-tuned.[^p8][^p9]
- Main result (sec 1, 6.1, Table 1): "At the main allowances of 100 model calls on the reasoning benchmarks and 1200 on ProgramBench, meta-reasoning yields higher point estimates in all 12 matched comparisons, with mean gains of 3.6–4.2 score points by benchmark." Means over the three models: IMO +4.0 (largest 8.6, Gemini), ARC-AGI-2 +4.2 (2.5 to 6.7 per model), LongCoT-mini +3.6 (0.4 with GPT-5.5 to 9.2 with Gemini, the largest single gain). ProgramBench with GPT-5.5: 71.5% mean per-problem test-pass rate against 63.7% for direct control and 58.0% for Codex; with Opus 4.8, 67.2% against 65.3% direct control and 65.5% Claude Code; with Gemini 3.1 Pro, 48.7% against 46.9%.[^p2][^p9][^p11]
- Table 1 values (Direct Control / Meta-Reasoning): Gemini 3.1 Pro IMO 82.7/91.3, ARC 77.5/84.2, LongCoT 53.5/62.7, ProgramBench 46.9/48.7; GPT-5.5 93.3/94.6, 75.8/79.2, 64.7/65.1, 63.7/71.5; Opus 4.8 78.0/80.2, 77.5/80.0, 65.3/66.5, 65.3/67.2.[^p11]
- Budget sweeps (sec 6.2, Figure 3): direct control often stops early; "On ProgramBench with GPT-5.5, it uses only about 18% of the 1200-call allowance. Across models, meta-reasoning uses roughly 89% to 101% at this setting" (workers dispatched under the cap may finish past it). Meta-reasoning with GPT-5.5 on ProgramBench rises from 64.1% at 400 calls to 71.5% at 1200; "Direct control stays near 64% across the sweep." With Opus 4.8 on ProgramBench, direct control "roughly doubles its calls used over the sweep, from 376 to 768. Its score rises only modestly, from 62.7% to 65.3%, and peaks at the intermediate budget. Continuing to work is not enough; what the agent does next also matters."[^p10][^p11]
- Small budgets (sec 6.2): "Meta-reasoning does not win at every budget. With Opus 4.8, it trails direct control at 400 calls, 56.6% versus 62.7%, then leads at 1200 calls, 67.2% versus 65.3%. GPT-5.5 is also slightly behind at the smallest ProgramBench allowance before pulling ahead." Finding: "At smaller allowances, overhead from explicit control stages can outweigh its benefit."[^p11]
- Graph structure (sec 6.3, Figures 4 and 5): meta-reasoning produces more worker outputs on all three reasoning benchmarks, and dependencies grow faster (IMO with Gemini: artifacts roughly double, recorded dependencies rise by an order of magnitude). On ProgramBench with GPT-5.5, 400 to 1200 calls gives more than 2.5 times the nodes and nearly four times the edges; direct control's graphs show no comparable growth.[^p11][^p12]
- Coverage, monitoring, selection (sec 6.4, Figure 6): coverage rises in most settings (largest with Gemini: +20 points on IMO, +10 on LongCoT-mini; Opus on LongCoT-mini about tied). Worker confidence for Gemini on IMO ranks near chance (Type-2 AUC 0.55); the controller's verdict reaches 0.88; the gap is smaller for GPT-5.5 and Opus. Agents submit from the deepest terminal artifacts in 83% of ARC-AGI-2 and LongCoT-mini runs. Frontier selection gain is not uniform: ARC-AGI-2 with GPT-5.5 +11 points for meta-reasoning against +3 for direct control; LongCoT-mini about tied for Opus and slightly in favour of direct control for Gemini.[^p12][^p13]
- Memory and state (sec 6.5, Figures 7 and 8): the controller re-reads its own notes more than worker outputs (4.4 to 9.8 reads against 1.9 to 3.3, among artifacts read at least once, on ARC-AGI-2 and LongCoT-mini). Direct control's history exceeds one million characters on the longest Opus 4.8 IMO runs; the meta-reasoning state stays at thousands to tens of thousands of characters (on ProgramBench the gap narrows to a factor of a few). The authors say the long history "may be part of why direct control stops improving as its budget grows, though we did not test it directly".[^p13]
- Discussion (sec 7.1, 7.2): the two agents "call the same models, dispatch the same workers, and draw on the same allowance, differing only in how the run is directed. We observe that every matched setting improves, and the margin widens as the budget allowance grows." The four stages are "one way to organize that activity. What the results support is the separation of these different functions."[^p14][^p15]
- Limitations (sec 7.3, Appendix A): staged control costs extra compute and "is not uniformly preferable to direct control"; a wrong controller assessment can propagate; compact state is lossy. On the LongCoT-mini chess subset meta-reasoning underperforms direct control (preliminary reading: "unproductive reconsideration"). "The size of the gain also depends on the model used." Appendix A: the comparison "establishes the value of the evaluated design as a whole, but not the necessity of each stage or an independent causal effect"; results "concern performance under common nominal call budgets, and not efficiency, latency, or performance at equal matched cost"; three frontier models and four benchmarks, a 30-problem proof set; "Positive point estimates across the main comparisons do not establish significance for every difference or generalization to weaker models, other tasks, or substantially longer horizons."[^p15][^p20]
- Baseline details (App. G.2, H, I): on ProgramBench the Meta-Reasoning and Direct Control agents get a read-only git tool that mini-SWE Agent, Claude Code and Codex do not. Claude Code and Codex run headless with native tools disabled and one MCP bash tool into the same container. RLM runs in a restricted workspace (no computation in the REPL) except one full-Python cell (Opus 4.8, LongCoT-mini).[^p36][^p37][^p38]
- Conclusion (sec 8): "An agent's performance therefore depends on how well it decides what work is worth doing, alongside how well it does the work. As runs grow longer, that decision becomes work in its own right."[^p16]
