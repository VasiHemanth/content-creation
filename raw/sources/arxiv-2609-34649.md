# What the paper says

- Problem: harness evolution from execution trajectories mostly adds experience, rules, prompts or skills, which the authors find less effective on long-horizon tasks. "As interactions grow, useful evidence can be buried by redundant or outdated context." Context management usually stays fixed while the rest of the harness evolves.[^p1]
- Setting: an agent is a base model M plus a harness H. The base model stays fixed and only the harness evolves. A context policy P turns all information that has entered the system into the model-visible context c_t, and the model acts on c_t (eq. 1).[^p3]
- Three policy dimensions (Table 1): Input Assembly (context entry preparation, for example tool-result formatting and observation compression), History Maintenance (compaction, summarization, persistent state) and Context Orchestration (context access and sharing across agents and subtasks).[^p3]
- Method, three stages, all run with the same fixed base model (sec 4, Figure 2):
  - Trajectory evidence reconstruction: a scan of each trajectory for information-flow events, then a paginated review that rebuilds the model-visible context at decision points, page by page, with a running note of task progress, unresolved events and context changes. The review separates context-management failures from failures that come from the model, tools or environment.[^p5]
  - Failure attribution and target identification: an analysis agent compares successful and failed trajectories. When that does not settle the attribution, it uses counterfactual replay: hold the execution prefix fixed, edit only the model-visible context at one decision point, and compare sampled next actions under the original and the edited context (eq. 4). A hypothesis names an information failure (missing, degraded, buried or polluted), a policy dimension and its evidence (eq. 5). An attribution is kept only when the evidence separates failed from successful executions.[^p5]
  - Context-policy update: a constrained editor modifies, combines or introduces mechanisms along the attributed dimensions. Without supporting evidence the update is empty and the policy stays the same (eq. 6).[^p6]
- Implementation: eight intervention points behind a versioned ContextProgram: observation entry, compaction planning, summary writer, memory writer, memory retriever, request assembly, parent-to-child dispatch and child-to-parent return (App. B.1, Table 11). The judge and the editor each get at most 30 turns; replay samples at most five actions per condition; the editor may commit an empty changeset (App. B.2).[^p17]
- Setup: Long-Horizon-Terminal-Bench (LHTB, 46 terminal workflows, partial reward in [0, 1] per task), DeepSWE (113 repository tasks, solved or not) and a BrowseComp-Plus subset built by the authors (174 of 830 questions, judged correct or not). Fixed held-in and held-out splits: 20/26, 48/65 and 76/98 tasks. Evolution reads only held-in trajectories. Harnesses: OpenCode, Pi-agent, Codex, OpenClaw; models: DeepSeek-V4-Flash-0731 and GPT-5.6-Luna. ContextEvo is built into Pi-agent and run for two evolution iterations. "Each task is attempted once" (App. A.2).[^p6][^p15]
- Main results (Table 2, full task sets, Pi-agent base to iter-2): with DeepSeek-V4-Flash, LHTB 41.7 to 45.3, DeepSWE 64.6 to 71.7, BrowseComp-Plus 82.2 to 88.5; with GPT-5.6-Luna, LHTB 30.3 to 34.3, DeepSWE 13.3 to 14.2, BrowseComp-Plus 37.9 to 42.0. Iter-1 full-set gains with DeepSeek-V4-Flash are 3.1, 4.4 and 3.4 points.[^p7]
- Held-out results are mixed (Table 2). With GPT-5.6-Luna, held-out DeepSWE goes 18.5, 15.4, 13.8 (base, iter-1, iter-2). Iter-1 lowers held-out BrowseComp-Plus for both models (82.7 to 81.6; 39.8 to 33.7).[^p7]
- Other harnesses (Table 2): with GPT-5.6-Luna, Codex scores 44.3 on DeepSWE and 60.1 on BrowseComp-Plus, against 14.2 and 42.0 for ContextEvo iter-2.[^p7]
- Skill-only comparison (sec 6.1, Table 3, all 46 LHTB tasks, reward and mean tokens per run): Pi baseline 0.417 and 8.57M; skill-only 0.370 and 9.61M; ContextEvo 0.448 and 7.52M; ContextEvo plus skills 0.419 and 9.69M. The skills come from the same held-in LHTB tasks, following trajectory-driven harness evolution (Zhang et al., 2026a). The skill-only arm injects a fixed procedural skill bank with context-policy generation turned off (App. C.1). Only 20 of 44 inspectable skill-only trajectories read a skill body. Sec 6.1 names no model; 0.417 and 0.448 equal the DeepSeek-V4-Flash LHTB full-set entries of Table 2 (41.7 and iter-1 44.8).[^p8]
- Context-management baselines (sec 6.2, Table 4, GPT-5.6-Luna, matched Pi-agent protocol; DeepSWE, LHTB, BrowseComp-Plus): Pi base 0.133, 0.303, 0.379; ReSum 0.062, 0.266, 0.385; ACON 0.124, 0.262, 0.374; TACO 0.115, 0.281, 0.374; ContextEvo 0.142, 0.343, 0.420.[^p8]
- Transfer (sec 6.3, Table 13): the LHTB-evolved policy moves LHTB by +3.12 pp (DeepSeek) and +2.56 pp (Luna), DeepSWE by -3.54 and -7.96 pp, and BrowseComp-Plus by +1.73 and -2.87 pp.[^p9]
- Ablation (sec 6.4, Table 5, LHTB, DeepSeek-V4-Flash): full pipeline 44.78%, native Pi-agent 41.66%, without paginated review 32.64%, without cross-case aggregation 42.49%, without counterfactual replay 41.06%, without the policy update 38.34%.[^p9]
- Cross-harness check (sec 6.4, App. C.4, BrowseComp-Plus subset, GPT-5.6-Luna with a Qwen3.8-27B judge): OpenCode 61 to 71 of 174 solved, OpenClaw 33 to 79.[^p9]
- Limits the authors state (sec 7): the selected policies "improve several full-benchmark point estimates over the Pi-agent baseline, while held-out changes vary by setting"; decision-point replay "measures only local next-action sensitivity", and the evidence does not establish a task-level causal reward contribution for any single policy mechanism.[^p10]
