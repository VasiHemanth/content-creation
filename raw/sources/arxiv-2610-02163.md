# What the paper says

- Problem: on long coding tasks, earlier exploration becomes stale, so "managing context is more than avoiding overflow: an agent must decide when to compact, what working state to preserve, and how to continue from it." Length-triggered methods compact only when the remaining budget falls below a threshold, so "compaction may then occur in the middle of an unresolved stage whose evidence is still needed." Proactive methods (an inference-time rubric, or SFT on runs with compression calls inserted offline) do not train what the agent does after it compacts.[^p1]
- Mechanism: the agent gets a `compact()` action it may call before the context limit. Compaction replaces earlier history with a model-generated working-state summary headed `# Auto Context Summary` and keeps the original task unchanged (sec 2.1).[^p3]
- Data collection (sec 2.2): "In our preliminary experiments, the base model rarely invoked compact() before the context limit, even when compaction rules were specified in the agent prompt." So the base policy is rolled out on SWE-rebench tasks while a judge reviews each proposed action using only the history so far. Three correction types: trigger (when to compact), working state (what to keep), continuation (whether the first actions after compaction follow the summary, "such as re-running a search whose result is already recorded in the working-state summary"). Corrections are applied before execution; the environment runs the corrected output and the policy continues from the corrected history. The judge is used only during data collection.[^p3][^p4]
- SFT on 1,052 judge-corrected runs from 379 SWE-rebench tasks (24% trigger, 53% working state, 23% continuation), two epochs, giving AutoCompact-SFT (sec 3.1).[^p5]
- RL (sec 2.3, 3.1): GRPO on SWE-Gym, 8 samples per task, binary reward (final patch passes the task tests), rollouts capped at 50 environment steps and 32K tokens. The shared advantage covers coding actions, the `compact()` decision, the summary and the continuation. No compaction-specific reward, no KL penalty or entropy bonus. Runs are split into segments where compaction rewrites the prefix; all segments share the run's advantage.[^p4][^p5]
- Setup (sec 3.1): base model Qwen3-Coder-30B-A3B-Instruct; one terminal-based REPL scaffold plus `compact()` for all variants; judge GPT-5.5-Codex, removed at evaluation. Full agent runs without a cost cap, "averaged over three runs". Six per-task inference budgets from $0.10 to $4.00, priced from Alibaba Cloud Model Studio rates with cached tokens at 20%.[^p5]
- Main results (Table 1, SWE-bench Verified / SWE-PolyBench Verified, %): Base (256K, full history) 30.4 / 19.5; Fixed Compaction (16K forced threshold) 28.8 / 18.6; CompactionRL (16K) 32.7 / 19.8; SelfCompact (256K) 31.7 / 20.6; SWE-Compressor (256K) 31.0 / 20.1; AutoCompact-SFT (256K) 32.2 / 21.7; AutoCompact (SFT then RL, 256K) 39.6 / 24.5. Gains over Base: 9.2 and 5.0 points. RL adds 7.4 and 2.8 over SFT.[^p6]
- In the 256K setting "no trajectory reaches the forced-compaction threshold" (sec 1, Figure 3 caption).[^p2]
- Budget sweeps (Figure 3, SWE-bench Verified; gains printed as extra solved tasks per 500): (a) AutoCompact-SFT vs Base at 256K, +18 to +9, endpoint labels 30.4% and 32.2%; (b) AutoCompact vs SFT at 256K, +42 to +37, labels 32.2% and 39.6%; (c) AutoCompact vs Base at 16K with a shared forced-compaction fallback, +55 to +46, labels 28.8% and 38.0%; (d) the same trained checkpoint following vs ignoring summaries, +100, +62, +30, +11, +9, +9, labels 37.7% and 39.6%. Panel (d) does not state its context window.[^p6]
- Sec 3.3 on (c): AutoCompact is higher than Base at every budget; "It also indicates that compaction based on task progress is more effective than compaction based solely on the length of the context."[^p8]
- Sec 3.3 on (d): in the Summary-ignored variant "compact() calls are skipped: no summary is generated, and execution continues with the existing history", with the same parameters. "The advantage is 19.9% at $0.10 and remains 1.9% at $4.00." The authors write these absolute differences with a % sign. They conclude the gains "cannot be attributed solely to better agent behavior learned during training: part of the benefit depends on actually executing compaction."[^p8]
- Compaction behaviour (Figure 4, sec 3.3): proactive compaction rate about 0% (Base), 44.3% (SFT), 58.5% (RL). Summaries missing key state 3.1% to 0.2%, missing next action 8.2% to 2.2% (SFT to RL), measured by "keyword-based screening, supplemented by random manual spot checks".[^p7]
- Case study (sec 3.4, Figure 5): one SWE-bench Verified task (django-13809) where the SFT summary records an unresolved syntax error yet proposes to finish, and the RL summary proposes verification. Paraphrased, qualitative.[^p8]
- Limits the authors state (sec 5): RL used 32K-token sequences against a 256K evaluation window; one scaffold. They note that "Widely used agent harnesses such as Codex and Claude Code currently compact the context automatically when it approaches the window limit", the length-triggered design, and leave combining them with learned compaction to future work.[^p9]
