# What the paper says

- Problem: automated research (AutoResearch) runs LLM agents over long horizons, "but more inference does not by itself produce more progress: agents replay growing histories, duplicate one another's work, or stop experimenting while token consumption continues." Most evaluations use short budgets or benchmarks that saturate early. The authors "trace these failures to two choices: where research state lives and who decides what to try next."[^p1]
- Motivating trace (sec 1, Figure 2(b)): "In one CORAL run on a GPU kernel task, the last improvement arrives at 231M tokens. Afterward, agents repeatedly declare their solutions optimal, and 98% of the final 1,500 sessions make no tool calls while token consumption continues." Token consumption continues to 1B. The figure's y axis is "Best SOL score". CORAL resumes each agent's own session after a restart, so a restarted agent "continues from the same conversation in which it decided to stop".[^p2][^p3][^p4]
- Benchmark saturation (sec 1, 2.2, Figure 2(a)): on 26-circle packing, four methods finish within 2.3 x 10^-10 of one another by 5M tokens.[^p2][^p3]
- Principle (Abstract, sec 1): "stateful search with stateless agents: no agent carries its conversation across invocations; instead, the harness owns the research state (candidate solutions and measured outcomes) and reconstructs a fresh and role-specific context for every invocation." State persists across invocations; context is what an agent sees within one invocation. "This does not make it contextless."[^p1][^p2]
- Framework (sec 3): each epoch the harness rebuilds the Advisor's context from the research state, and the Advisor assigns concrete experiments to parallel Workers. Each Worker runs several local trials in an isolated workspace. An independent evaluator scores every candidate. "Each Advisor epoch and each Worker trial is one invocation. Every invocation starts a new agent session." Unlike native subagent orchestration, where the orchestrator stays stateful, "every SLA agent, including the Advisor, is stateless".[^p4]
- Advisor context (sec 3.1): task specification, current global best code and score, and a harness-built evidence summary (recent attempts, outcomes grouped by search direction, Worker status, recent progress, task diagnostics). It separates measured non-improvements from inconclusive failures. Worker context: task specification, its assignment, its retained candidate, and compact local feedback. Workers cannot see other Workers' workspaces or the full history; "Workers build on prior progress without inheriting the conversations that produced it."[^p5]
- Assignment (sec 3.2): because the Advisor is stateless, it revisits assignments each epoch from current evidence. It can spread Workers across directions or concentrate them. A redirected Worker restarts from the global best.[^p5]
- Implementation (sec 3.3, B.1): Codex or Claude Code for both roles. "Statelessness and isolation are enforced rather than requested": the Advisor starts each epoch in a new session; Workers run under Linux Landlock restrictions with restricted network; the harness clears saved sessions between trials; evaluators are protected; Codex's built-in multi-agent feature is off. Default 3 Workers and three local trials per Worker per epoch.[^p6][^p17]
- Setup (sec 4.1): FrontierSWE (libexpat to x86-64 Assembly, Git to Zig, Dart to Haskell, Lua Native Compiler; 700M tokens), Anthropic's VLIW SIMD kernel optimization task (1B tokens), SOL-ExecBench #1, #58, #210 (500M), FrontierCS Structured-LWE (200M). Two coding-agent configurations: Codex CLI v0.152.1 with GPT-5.5, Claude Code v2.1.258 with Claude Opus 4.8. Advisor and Workers use the same model in the main runs. Baselines: EvoX (a fresh coding agent per generation), CORAL (one long-running session per agent, resumed after every heartbeat, stall or restart), SwarmResearch (a long-running Shepherd session; each Optimizer resumes its parent's conversation). Same agents, models, seeds, task materials, protected evaluators, and an external cumulative-token counter for all.[^p6][^p7]
- Replication (sec 4.1): Anthropic kernel with Codex has three runs per method; the checkpoint ablations have three runs per configuration; "Other main-result configurations use one run per method."[^p7]
- Main results (sec 4.2, Tables 1 to 3): SLA has the best full-budget result on every evaluated task. Anthropic kernel with Codex: 1112.0 +/- 8.9 cycles against 1275.7 +/- 133.9 for SwarmResearch; all three SLA runs beat all nine baseline runs (worst SLA 1122 against best baseline 1191). Tokens to first match the strongest baseline's full-budget result: Codex 67.9M against 986.3M for SwarmResearch (93.1% reduction, mean curves); Claude Code 138.5M against 888.3M for CORAL (84.4%, one run per method). FrontierSWE: +4.95 points on average over the strongest per-task baseline. SOL-ExecBench: +5.5% on average; savings reach 95.9% on #58; the exception is #1, where EvoX reaches the target sooner (46.1M against 152.7M) but SLA ends higher. Structured-LWE: +1.5 points.[^p7][^p8][^p9]
- Horizon reversal (sec 4.2, Table 2, Figure 1(b)): on all four FrontierSWE tasks (Codex, one run per method) SLA trails the strongest baseline at 175M tokens (25% of the budget) and leads at 700M. Differences at 175M: -0.85, -3.90, -11.27, -2.75; at 700M: +6.75, +0.86, +6.68, +5.49 (libexpat, Git to Zig, Dart to Haskell, Lua). "Across our experiments, short horizons can misjudge methods, components, and configurations."[^p3][^p8]
- Ablations (sec 4.3, Table 4): from shared checkpoints (Anthropic kernel and FrontierSWE libexpat, 10% and 20% of budget, +100M tokens, three runs each), removing Advisor context reconstruction, Worker context isolation, or Advisor assignments reduces mean progress in every comparison. "All variants keep every agent stateless." A full 1B run without Worker isolation ends at 1336 cycles, 224 worse than full SLA's mean.[^p8][^p9][^p10]
- Coordination cost (sec 4.4, Table 5): the Advisor consumes 0.24% (Anthropic kernel, 1B) and 0.51% (FrontierSWE libexpat, 700M) of tokens, against 8.39% and 10.70% for SwarmResearch's Shepherd. Because the Advisor reuses less cache, its share of estimated model cost is higher: 1.20% and 2.29% (Shepherd 6.14% and 7.35%), at GPT-5.5 list rates.[^p9][^p10]
- Worker scaling (sec 4.4, Table 6): 1 to 15 Workers cuts elapsed time 6.6x (kernel) and 7.3x (FrontierSWE mean); on the kernel, all widths finish within 1107 to 1113 cycles; the best width varies by task. Cheaper GPT-5.4 mini Workers beat GPT-5.5 Workers on Git to Zig at $100 but not on the kernel (Appendix C.1).[^p10][^p18]
- Traces (Appendix D): D.1, a CORAL agent on Lua reuses a two-hour-old note to restore a lost feature (88.46 to 89.01), and two more agents then restore the same feature. D.2, two CORAL agents on libexpat implement the same feature twice in 13 minutes, the second time despite a posted claim note. D.3, in the first ablation run without Advisor assignments, the Advisor proposes three different tasks in epoch 24, the harness withholds them, and all three Workers add the same XML entity-decoding code from the same start (trials 269 to 271); none improves the starting score. "Similar overlap occurs in both other runs." The authors add: "These cases help interpret the ablation results, but do not measure how often these behaviors occur."[^p19][^p20][^p21][^p22]
- Limitations (sec 5): "most configurations use a single run. Only Anthropic kernel optimization with Codex and the checkpoint ablations are replicated. Comparisons are matched on tokens, and cost estimates exclude the compute for running and evaluating experiments. Our ablations change what each agent sees, not whether it keeps its conversation across invocations. All tasks have executable evaluators, so goals that are vague or slow to evaluate remain untested."[^p11]
- Discussion (sec 5): the authors expect the principle to apply "wherever agents run far longer than one context window"; Worker trials could serve as RL episodes; all persistent state lives in the harness where people can inspect and roll it back, though candidate code that games the evaluator remains a risk. "We therefore report results at multiple cumulative token budgets and encourage future evaluations to do the same" (sec 1).[^p3][^p11]
