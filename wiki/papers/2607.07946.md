# DeepSWE

Topic: [coding agent benchmarks](/wiki/topics/coding-agent-benchmarks.md). Authors: Wenqi Huang, Charley Lee, Leonard Tng, Serena Ge (Datacurve). arXiv 2607.07946v1.

## TL;DR
DeepSWE swaps SWE-bench's recipe (mine merged fixes, grade with the tests that shipped with them) for tasks written from scratch and graded by hand-written verifiers. In the authors' audit an independent LLM judge disagreed with the DeepSWE verifier on 1.4% of rollouts versus 32.4% for SWE-Bench Pro. That is a disagreement rate, not an error rate.[^paper]

## 1. What capability is it trying to measure?
Whether a coding agent can solve a novel, repository-scale engineering task from a short prompt: find the relevant code, edit across files, keep unrelated tests passing.[^paper]

## 2. What does one example look like?
Open question. The paper puts a representative prompt from each benchmark in Appendix E; it was not read in this pass. Prompts average roughly 2,000 characters.[^paper]

## 3. How was the dataset constructed?
113 tasks across 91 active repositories (500+ stars, permissive license) in TypeScript, Go, Python, JavaScript and Rust, each pinned to a commit. Tasks are authored from scratch and never merged upstream. Each ships a prompt, an executable verifier and a reference solution used only in review. Tasks pass LLM-assisted analysis plus independent human review on four dimensions (prompt-verifier bijection, acceptance breadth, realism, environment cleanliness).[^paper]

## 4. How is it run and scored?
Harness: mini-swe-agent with one bash tool and a shared prompt for every model. Verifiers run three times during authoring to catch flakiness, and each trial also runs regression checks. About four rollouts per task. Binary pass or fail. The live leaderboard (v1.1) grades in separate verifier environments.[^paper][^readme][^board]

## 5. Which metric is reported and what does it omit?
pass@1 (mean per-task pass rate) with a run-to-run 95% interval, and pass@4. It omits partial credit, code quality, style, performance and documentation. The interval ignores variation from which 113 tasks were chosen.[^paper]

## 6. What can inflate, contaminate or destabilize the score?
- Contamination: the authors argue originals cannot be in pretraining data at evaluation time; once prompts, verifiers and trajectories are released, future training could ingest them.[^paper]
- Packaging leaks: on SWE-Bench Pro an external report cited by the paper found 33 of 38 cheating trials reading the gold commit from container `.git` history. DeepSWE ships a shallow clone.[^paper]
- Harness and effort: one harness for all models, and reasoning effort differs by family. Scores are model plus harness plus effort, not bare model ability.[^paper]
- Version drift: the paper's v1 results (May 2026) and the live v1.1 board differ in grading and models. For example gpt-5.5 [xhigh] is 70.0% in the paper and 67% on the v1.1 board.[^paper][^board]
- The audit judge is GPT-5.5, also the top configuration in the paper, so self-preference cannot be excluded. DeepSWE's audit rests on 2 false positives and 8 false negatives in 735 rollouts.[^paper]

## 7. What experiment would reveal more than one leaderboard number?
Re-grade the same rollouts with two different judge models, neither of them a ranked agent, and compare disagreement rates on both benchmarks.

## 8. What should be read next?
SWE-Bench Pro (Deng et al., 2025; Scale AI) and the Scale AI 2026 report on cheating trials, both cited in the paper and not read here. The mini-swe-agent repository for harness details.

## 9. What is the sharpest teaching angle?
A benchmark score is only as good as its grader. The cost angle: on the v1.1 board the three 74% entries (gpt-6-astra, gemini-3.8-flash, claude-opus-5) have overlapping intervals and average cost per task of $4.43, $2.36 and $11.84.[^board] The paper itself finds cost and tokens do not track pass rate.[^paper]
