# Dream-RSI

Topic: [agent self-improvement](/wiki/topics/agent-self-improvement.md). Authors: Tong Zheng, Xidong Wu and 15 others (Google, Google DeepMind, University of Maryland, University of Virginia). arXiv 2609.14858v1, submitted 2026-09-14.

## 1. Identity
"Dream-RSI: Recursive Self-Improvement through Evolving Worlds", arXiv 2609.14858, version v1 (the version the video was made from).[^paper]

## 2. What problem does it address?
Agents that search for better code spend many attempts, and the policy that decides where to search is usually fixed because testing a new policy needs a full new search.[^paper]

## 3. What is the method?
A completed search is stored as a discovery tree (one node per attempt, with its score). The tree is used as a replay simulator: a candidate exploration policy walks the recorded tree and sees the stored outcomes, with no new runs of the coding agent or evaluator. A separate LLM agent rewrites the policy code over several versions and scores each one on all past trees ("dreaming"); the best version goes back to the real search, whose new tree joins the pool for the next round.[^paper]

## 4. What is the evidence?
All results are the authors' own runs with Gemini-3.1 Pro and Gemini-3.7-Flash through the Gemini CLI, against a controlled baseline that keeps the exploration policy fixed (Recursive Fixed Exploration).[^paper]
- Lasso path solver: 317 discovery-agent calls against 550, with average runtime on six held-out datasets 2931.0 ms against 3587.1 ms (Gemini-3.1 Pro). With Gemini-3.7-Flash: 1879 calls against 3200, 2350.6 ms against 2516.7 ms.
- GPU kernels (KernelBench): comparable performance with 2.43x (VGG16) and 1.79x (LayerNorm) fewer generations; 2.09x (ConvDiv) and 1.44x (ConvMax) higher performance at comparable budgets.
- Math: small gains on Sum-Difference, a tie on Circle Packing, and slightly behind SimpleTES (51,200 generations) and AlphaEvolve on Autocorrelation.

## 5. What does it not show?
- Replay only reorders, selects, batches and stops over recorded branches; it never predicts the outcome of a branch that was not tried.[^paper]
- Discovery cost counts discovery-agent calls. The policy-development agent that runs the dreaming phase is a separate agent; its cost is not part of that number. Open question: the dreaming phase's own token and time cost.
- Every run uses Gemini models; no other backbone is tested.
- Comparisons with SimpleTES and other systems mix models and budgets; only Recursive Fixed Exploration is a controlled comparison.
- The main results report no confidence intervals or run-to-run variance.
- The settings of M, the round limits and the replay-score weights: Open question (not found in the main text).

## 6. One experiment that would test the main claim
Report the dreaming phase's total LLM tokens and wall-clock time next to the discovery-agent calls it saves, repeat the Lasso and kernel runs with a non-Gemini discovery agent, and give run-to-run intervals.

## 7. What should be read next?
EvoX (meta-evolution of search strategies), SimpleTES (the Lasso and math baseline), and the Dreamer world-model papers by Hafner et al., which the paper names as its analogy.

## 8. Sharpest teaching angle for a 60 second video
The agent's old search tree is a free practice ground: it can try many search policies against recorded outcomes, then run only the best one for real. Pair it with the two limits (replay cannot see untried paths; the cost figure leaves out the dreaming agent).
