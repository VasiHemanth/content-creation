# Context Language Models

Topic: [agent context management](/wiki/topics/agent-context-management.md). Source record: [arxiv-2609-37725](/raw/sources/arxiv-2609-37725.md). Short name used on screen: CLMs.

## 1. Identity
Rulin Shao and twelve co-authors, University of Washington, Meta Superintelligence Labs, MIT, Trillium Labs. arXiv 2609.37725 v1, cs.AI, 2026-09-29.

## 2. Problem
Context management is usually done by a harness with fixed rules (compaction, offloading, retrieval) rather than by the model.[^pdf]

## 3. Method
Mirror the context as a file the model can edit with Bash; edits sync to the live context. Multiple context files support agent swarms. Extras: prompt-evolved skill documents, a stepwise GRPO recipe with a success-gated efficiency advantage, and Suffix Cache Reuse for serving.[^pdf]

## 4. Evidence
Zero-shot BrowseComp-Plus 59.4% (11.4% relative above summarization, 21.5% fewer prefix-reuse FLOPs); TBLite 73.7% vs 67.0%; EdgeBench-10 44.6 vs 42.3 at 179 vs 437 PFLOPs; Software World 65% greater speedup at the same spend; RL 28.8% to 42.5% with Qwen3.5-9B; Suffix Cache Reuse 35% less server compute.[^pdf] All results are the authors' own.

## 5. What it does not show
FLOPs are theoretical counts, not wall-clock time or cost. Baselines are re-implementations in a shared Mini-SWE-Agent harness. The authors flag prompt injection through editable context as open. Independent reproduction: Open question.

## 6. One experiment
Run the same BrowseComp-Plus comparison measuring wall-clock time and dollars with prefix caching on, to see whether the FLOPs advantage carries over.

## 7. Read next
BrowseComp-Plus (Chen et al., 2025) and the Recursive Language Models paper (Zhang et al., 2025), both compared here.

## 8. Teaching angle
"Stop hard-coding what your agent forgets": give the model the editor and let it manage its own context.
