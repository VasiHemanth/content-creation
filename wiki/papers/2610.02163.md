# AutoCompact

Topic: [agent context management](/wiki/topics/agent-context-management.md). Authors: Xuan Zhang, Longtao Zheng and 3 others (Singapore Management University, Nanyang Technological University, Harvard University). arXiv 2610.02163v1, submitted 2026-10-01.

## 1. Identity
"AutoCompact: Learning When to Compact Context in Long-Horizon Coding Agents", arXiv 2610.02163, version v1 (the version the video was made from).[^paper]

## 2. What problem does it address?
Coding agents that compact only when the context nears its limit may compact in the middle of a stage whose evidence is still needed, and existing proactive methods do not train what the agent does after it compacts.[^paper]

## 3. What is the method?
The agent gets a `compact()` action that replaces earlier history with a working-state summary and keeps the task. To make training data, the base model runs on SWE-rebench tasks while a judge reviews each proposed action and writes a fix for three failure types: compacting at the wrong time, a summary that omits needed state, and actions after compaction that ignore the summary. The fix runs in place of the original, so the rest of the run grows from it. SFT on 1,052 corrected runs is followed by GRPO with one binary pass-or-fail reward that trains coding and compaction together, with no compaction-specific reward. There is no judge at test time.[^paper]

## 4. What is the evidence?
All results are the authors' runs with one base model (Qwen3-Coder-30B-A3B-Instruct) and one REPL scaffold, averaged over three runs.[^paper]
- Table 1, full runs without a cost cap, SWE-bench Verified: Base with its full 256K context 30.4%, AutoCompact 39.6% (+9.2). SWE-PolyBench Verified: 19.5% to 24.5% (+5.0). AutoCompact-SFT alone: 32.2% and 21.7%.
- Baselines on SWE-bench Verified: Fixed Compaction 28.8 and CompactionRL 32.7 (both 16K forced threshold), SelfCompact 31.7 and SWE-Compressor 31.0 (both 256K).
- Under a shared 16K forced-compaction fallback, AutoCompact beats Base at all six budgets (Figure 3(c)); the authors read this as compaction based on task progress being more effective than compaction based on length.
- Running against skipping the compact calls of the same trained checkpoint: 19.9 points at $0.10 per task, 1.9 points at $4.00 (sec 3.3, Figure 3(d)).
- Proactive compaction rate rises from about 0% (Base) to 44.3% (SFT) and 58.5% (RL); summary omissions fall, measured by keyword screening with spot checks (Figure 4).

## 5. What does it not show?
- How much of the 9.2-point gain comes from compaction itself. At $4.00 the same checkpoint with its compact calls skipped loses only 1.9 points, and Figure 3(d) labels that variant 37.7%, well above Base's 30.4%. Our inference, not a claim in the paper: at full budget most of the gain stays in the trained weights. This assumes panel (d) is the 256K setting, which the text does not state (its 39.6% endpoint matches the 256K value in Table 1 and Figure 3(b)). The authors read the same experiment as showing that the gains "do not come from training alone".
- A baseline that gets the same SFT and RL on coding tasks without the `compact()` action: Open question. Without it, the RL gain (7.4 points over SFT) cannot be split between better coding and better compaction.
- Generality: one base model, one scaffold, two benchmarks (SWE-bench Verified and SWE-PolyBench Verified); the budget sweeps cover SWE-bench Verified only. RL trained on 32K-token sequences against a 256K evaluation window.
- Production harnesses: the paper names Codex and Claude Code as length-triggered designs but tests neither.
- Variance: three runs are averaged; no spread or interval is reported.
- The judge is GPT-5.5-Codex, a different model from the base model; the cost of judging per corrected run is not reported. Open question.
- Summary-quality numbers rely on keyword screening and one qualitative case study.

## 6. One experiment that would test the main claim
Train a matched control with the same SFT data volume and the same RL on SWE-Gym but no `compact()` action, then compare it with AutoCompact and with AutoCompact's compact calls skipped, at 256K and 16K, with intervals over runs.

## 7. What should be read next?
CompactionRL (Li et al., 2026b) for length-triggered compaction with RL; Self-compacting language model agents (Li et al., 2026a) for the inference-time rubric; Context as a tool / SWE-Compressor (Liu et al., 2026) for offline-inserted compaction calls; SWE-MeM (Gao et al., 2026), concurrent work. On this wiki: [Context Language Models](/wiki/papers/2609.37725.md), where the model edits its context as a file, and [ContextEvo](/wiki/papers/2609.34649.md), where a harness policy learns what the model sees.

## 8. Sharpest teaching angle for a 60 second video
Popular coding agents compact when the context nears the limit, which can land in the middle of a stage. AutoCompact trains the agent to compact when a stage is done, using a judge that fixes actions before they run, then one pass-or-fail reward. The same base model goes from 30.4% to 39.6%. Caveat: skipping its compact calls costs 19.9 points on a tight budget but only 1.9 at the largest one.
